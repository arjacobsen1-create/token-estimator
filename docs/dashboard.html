ⓘWhat this measures, and what it doesn't

It measures
  • Input tokens: the material handed to the model, counted. Exact for GPT models (the real o200k_base tokenizer); labelled estimates for other models, with the measured error published in ACCURACY.md.
  • Predicted output tokens: forecast from the type of task (summarise about 0.2x the input, extract 0.3x, draft 1.5x, code 2x, classify a fixed short label). A forecast, not a meter reading.
  • Cost: input plus predicted output, at the selected model's price, at your volume. Prices are editable defaults.
  • For the SAP edition: 21 generic shapes of SAP work with typical input sizes, published in SAP-TASKS.md. No client data, no system data.
It doesn't measure
  • Quality: a cheaper run is not a better run. Nothing here scores the answer.
  • Actual consumption: only a metered bill or platform telemetry proves what a workload really used.
  • Vendor consumption units (SAP AI Units and the like): vendors set conversion rates per scenario. This measures the token driver underneath, which is what every basis converts from.
  • Business value: whether a task was worth doing at all stays a human decision.

If you pay a flat subscription, read the dollar figures as an API-equivalent yardstick: they size and compare workloads and show what burns the allowance you already bought. If you pay per token or in consumption units, they are a direct forecast. Either way the tool prices the work, not the channel: Joule, in-tenant agents, plugins and direct APIs all consume the same tokens. Governance differs by channel, so anonymise before anything leaves the tenant (protections list in SAP-TASKS.md).
